# Migrate from the 0.1 source snapshot to 0.2

The 0.1 milestone was certified repository evidence but was never published to
the public npm registry. This guide applies to applications that installed a
workspace, tarball, or Git revision from that line.

0.2 is a synchronized three-package public preview and changes the shared
runtime contract from v1 to v2. Upgrade all installed Concierge packages in one
lockfile operation. Mixed contract versions fail before bridge registration or
dispatch.

## 1. Upgrade the fixed package set

The npm scope changed in 0.2. In `package.json`, replace every installed 0.1
dependency key with its 0.2 equivalent and set its version to `^0.2`:

- `@fullselfbrowsing/concierge` becomes `@full-self-browsing/concierge`.
- `@fullselfbrowsing/concierge-react` becomes
  `@full-self-browsing/concierge-react`.
- `@fullselfbrowsing/concierge-svelte` becomes
  `@full-self-browsing/concierge-svelte`.

Then regenerate the lockfile once:

```sh
pnpm install

# Add this when using AI SDK:
pnpm add ai@^7

pnpm why @full-self-browsing/concierge
```

The last command should show one physical 0.2 core. Delete old tarball or Git
overrides and regenerate the lockfile if both 0.1 and 0.2 remain.

The Node consumer floor remains 22.12. The packages remain ESM-only.

## 2. Replace split catalog reads with `resolveCatalog`

Contract v1 exposed separate catalog/stage reads. Contract v2 returns one
instance-local capability so stage selection, availability, tools, and dispatch
cannot observe different states:

```ts
// 0.1
const stage = concierge.stageFor(context);
const tools = concierge.catalogFor(context);

// 0.2
const catalog = concierge.resolveCatalog(context);
catalog.stage;
catalog.tools;
catalog.revision;
```

Do not serialize, compare across Concierge instances, or persist
`catalog.revision`. It is a local capability for the exact runtime snapshot.

`Session.catalog()` now returns the same `ResolvedCatalog` shape, and
`onCatalogChange` receives it.

## 3. Use object-form dispatch

Dispatch now requires the catalog revision explicitly:

```ts
// 0.1
await concierge.dispatch(context, "openProject", { projectId }, meta);

// 0.2
const catalog = concierge.resolveCatalog(context);
await concierge.dispatch(context, {
  name: "openProject",
  input: { projectId },
  catalogRevision: catalog.revision,
  identity: {
    sessionId,
    responseId,
    userTurnId,
    callId,
    outputIndex: 0,
  },
  signal,
  deferUntilDelivered,
});
```

An old or foreign revision is rejected before handler lookup. Preserve all
identity fields instead of rebuilding them from display text.

## 4. Update batches and terminal handling

`ToolBatch` now requires `sessionId` and `catalogRevision` in addition to its
response, optional turn, ordered calls, signal, and delivery hook.

`dispatchBatch` no longer uses an empty or truncated array as an implicit
terminal signal. Handle the explicit union:

```ts
const outcome = await concierge.dispatchBatch(context, batch);

if (outcome.kind === "completed") {
  consume(outcome.rows);
} else {
  consume(outcome.rows);       // completed prefix
  stopAfter(outcome.enteredBy); // exact terminal dispatch occurrence
}
```

Each row now carries `dispatchId`, `callId`, `outputIndex`, and `result`.
Terminal identity includes action name and dispatch lineage.

## 5. Replace split transport publication and response callbacks

Contract v1 transports received tool arrays and sent results through a
separate per-call response method. Contract v2 publishes the atomic catalog
snapshot and makes the batch subscription itself return the complete outcome:

```ts
const transport: Transport = {
  capabilities,
  status,
  setCatalog(catalog) {
    publishTools(catalog.tools, catalog.revision);
  },
  onStatusChange(listener) {
    return subscribeToStatus(listener);
  },
  onToolBatch(listener) {
    return subscribeToBatches(async (batch) => listener(batch));
  },
};
```

Remove public `setTools` and `respond` implementations. Do not treat an empty
array as a terminal response. `createSession` now owns catalog publication and
returns the awaited `BatchDispatchOutcome` through `onToolBatch`.

The session handle is now deliberately small: use `setContext`, `catalog`,
`onCatalogChange`, and the awaitable `stop` drain. Stage-specific listeners and
split `stageFor`/`catalogFor` reads are gone.

## 6. Subscribe to dispatch lifecycle events

Use `onDispatch` for overlays, telemetry, and devtools instead of wrapping
handlers:

```ts
const unsubscribe = concierge.onDispatch((event) => {
  renderStatus(event.phase, event.name);
});
```

Events are non-blocking, observer-safe, and include redacted input, atomic
stage/revision, correlation identity, compound-action lineage, terminal intent,
and the final structured result where applicable. Listener errors do not alter
dispatch.

## 7. Move scripted sequences into compound actions

Handlers can use `workflow.run`, `workflow.delay`, `workflow.cleanup`, and
`workflow.signal`. Child calls go through the same availability, validation,
consent, deduplication, event, and terminal boundaries. Assign stable `stepId`
values and configure bounded depth/step limits on `createConcierge` when the
defaults are not appropriate.

Remove orchestration loops from React, Svelte, AI, and transport adapters.

## 8. Adopt the AI SDK adapter

The optional `@full-self-browsing/concierge/ai-sdk` subpath supports AI SDK 6 and 7.
It converts the resolved catalog and provides:

- `createAISDKAdapter` and `toAISDKTools` from `/ai-sdk`;
- `createSignedBatchIssuer` from `/ai-sdk/server`;
- `createSignedBrowserBridge` and replay stores from `/ai-sdk/browser`.

Raw AI SDK tool callbacks are not a trusted browser dispatch channel. Follow
the [AI SDK integration guide](../integrations/ai-sdk.md), or the
[hand-written integration migration](./custom-ai-sdk-to-concierge.md).

## 9. Re-run security review

Contract v2's signed bridge does not change the server authorization rule.
Client consent, signed browser execution reports, and client context remain
untrusted at a protected server boundary. Reconfirm current-principal
authentication, exact-payload authorization, replay handling, and
transactional/idempotent effect execution.

Add negative tests for foreign revisions, mixed contract versions, stale
catalogs, terminal outcomes, compound limits, signature/key/audience/session
mutations, replay, and result-correlation mismatches.
