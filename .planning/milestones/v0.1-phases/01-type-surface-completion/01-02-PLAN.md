<objective>
Close defect (a): `ActionResult.reason` is open `string`, and `AbandonReason` is declared, exported,
and consumed by nothing. Replace with a closed twelve-code union, and give `message` the declared
bound and stated policy it has been missing.

Purpose: an open `reason` lets a handler smuggle arbitrary text into a field the agent reads, and
destroys the exhaustiveness that Phase 6's dispatcher and Phase 8's kernel will depend on. This is
the V5 input-validation control for the whole contract.
Output: `FailureReason`, `ReasonCode`, retyped `ActionResult.reason`, `MESSAGE_MAX_CHARS`, and the
first test-d file.

## ⚠ The count is TWELVE. Do not write thirteen anywhere.

`AbandonReason` has **3** members (`declined`, `cancelled`, `superseded`). `FailureReason` has **9**
(enumerated in Task 1). **3 + 9 = 12.**

Earlier drafts of this plan said "thirteen" in eight places, including two hard acceptance criteria.
Membership was always right; only the count word was wrong, and it propagated from a CONTEXT
paragraph that has since been corrected with an explicit callout (`01-CONTEXT.md` § D-01,
"⚠️ Count corrected 2026-07-28"). An executor reading "thirteen" as a criterion could only satisfy it
by **inventing a thirteenth code** — permanently corrupting a union this phase declares final, on the
one type whose entire design property is that additions break every exhaustive mapper. If any
document you encounter still says thirteen, that document is stale; the number is twelve.

**Serial phase.** This is plan 2 of 9 in a single serial sequence. Do not run it alongside any
other Phase 1 plan — every plan edits `packages/concierge/src/types.ts`.
