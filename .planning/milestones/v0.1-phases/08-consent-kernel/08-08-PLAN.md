<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client consent artifacts → relying server | All client claims can be forged, replayed, reordered, or bound to another principal/payload. |
| concurrent redemptions → protected effect | Two requests may race between unused-state validation and challenge burn. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-09 | Spoofing / Replay | README server boundary | mitigate | Server-issued stored challenge plus independent authentication, payload, freshness, and single-use validation, followed by current-policy reauthorization of the authenticated principal for the exact action immediately before effect under serialized atomic redemption. |
| T-08-SC | Tampering | documentation dependency surface | mitigate | Test uses built-in Node modules only; no package install or server code is introduced. |
</threat_model>
