<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App configuration → core types | Mutable or over-broad capability/evidence objects could let callers rewrite what the kernel believes. |
| Delivery report → consent evidence | A hash or observed act must remain distinct from delivery completion and cannot upgrade it by shape alone. |
| Session result → app outcome sink | Model-authored text or mutable ActionResult aliases must have no type-level route into the app-authored outcome. |

## STRIDE Threat Register

| Threat ID | Severity | Category | Component | Disposition | Mitigation and verification |
|-----------|----------|----------|-----------|-------------|-----------------------------|
| T-08-01 | high | Spoofing | ConsentProfile / ReadbackAttestation | mitigate | Closed provenance/act unions, exact readonly members, and negative type pins prevent an arbitrary shape from being mistaken for human-attested evidence. Runtime nonempty/distinct checks land in Plans 08-03/04. |
| T-08-04 | high | Elevation of privilege | ConsentProfile / ConsentAck | mitigate | Capabilities remain a separate ceiling and the attested ConsentAck branch still requires readbackHash; exact predicates reject flattening or writable grades. |
| T-08-06 | high | Spoofing | DeliveryReport.attestation | mitigate | ReadbackAttestation is separate from ReadbackReceipt and DeliveryReport.outcome; type tests prove a hash alone is not an act. |
| T-08-08 | high | Information disclosure | SessionConfig.presentOutcome | mitigate | Required OutcomeSink receives only exact failure rows and no model-text member; the exhaustive table receives fixed non-echoing failure prose now, while runtime deep-copy/freeze, emission, and ordering land in Plan 08-05. |
| T-08-10 | high | Tampering | public evidence objects | mitigate | Readonly/exact-key/EOPT pins plus built declaration and foreign-consumer gates block accidental mutable or detail-bearing channels. |
| T-08-SC | low | Tampering | package supply chain | accept | No install or dependency change is planned; manifest and pnpm-lock.yaml are mechanically unchanged. |
