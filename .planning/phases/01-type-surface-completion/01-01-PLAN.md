packages/concierge/test-d/_assert.ts exports:
  type Expect<T extends true>          — fails with TS2344 when T is false
  type Equals<A, B>                    — invariant equality (conditional-identity trick)
  type Assignable<From, To>            — [From] extends [To] ? true : false
  type Not<T extends boolean>          — boolean negation

Import form from a sibling test file: import type { Expect, Equals, Assignable, Not } from "./_assert.js";

<!-- Phase-wide export rule this plan establishes. Every later plan MUST hold it. -->

  `_assert.ts` EXPORTS its four aliases — that is its entire job, and type aliases are fully
  written out so they carry no `isolatedDeclarations` annotation tax.

  Every `test-d/*.test-d.ts` file EXPORTS NOTHING. Their `import` statements already make them
  modules, so no `export {}` is needed there. The rule is load-bearing rather than stylistic:
  an exported alias that reads an inferred `const` — e.g. `export type X = typeof confirm;` where
  `const confirm = defineAction({…})` — fires TS9010 under `isolatedDeclarations`, reported on the
  `const` rather than on the export. Plan 01-06 demonstrates this deliberately and then removes it.

  Mechanical gate, runnable from the repo root at any point once a test file exists:
    test -z "$(grep -l '^[[:space:]]*export' packages/concierge/test-d/*.test-d.ts)"
