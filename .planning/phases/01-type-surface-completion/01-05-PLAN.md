<objective>
**THE HINGE. This is ONE edit, not three.**

`ConsentAck` is where D-03, D-05, and D-07 all land. D-03 makes `readbackHash`'s doc comment name its
producer. D-05 adds `challenge?: ServerChallenge` **and** refactors the interface into a
discriminated union so `grade: "attested"` type-*requires* `readbackHash`. D-07 preserves the
`<Snapshot, Payload>` type parameters across that refactor.

Sequencing these as separate tasks produces conflicting intermediate states that do not compile —
D-05 changes the declaration's *kind* (interface → type alias), so any two done separately force a
rewrite of the third. Write the whole declaration once.

Purpose: today the `attested ⇒ readbackHash` invariant is only a doc comment. `attested` is the only
grade an irreversible action should accept, and it is the only one that survives OWASP ASI09 — the
agent reauthoring the readback before the human sees it — precisely because it routes around
`message` entirely via a hash over app-rendered bytes. A grade that can exist without its binding
evidence is the gate failing while appearing to work.
Output: the rewritten `ConsentAck`, and the second half of `consent.test-d.ts`.

**Serial phase.** Plan 5 of 9 in a single serial sequence. Do not parallelize.
</objective>

| Boundary | Description |
|----------|-------------|
| agent → human (readback rendition) | The agent reauthors `ActionResult.message` before the human receives it (OWASP ASI09) |
| client ack → any server that reads it | `JSON.stringify(ack)` is the path of least resistance; a server has no way to verify a client-asserted grade |
