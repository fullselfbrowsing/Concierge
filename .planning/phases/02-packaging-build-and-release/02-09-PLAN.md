<objective>
Prove the artifact actually installs and actually runs where the manifest says it does.

Purpose: success criterion 1 is *"a scratch project **outside the repo** installs the packed
tarball, imports `@fullselfbrowsing/concierge`, and typechecks against its shipped declarations"*,
and success criterion 3 is deliberately stricter than it reads: *"imports successfully on the exact
Node version the package declares as its floor, **not merely on the developer's newer runtime**."*
Both are integration claims that nothing in the repo can make on its behalf.

Two findings shape the implementation. A scratch directory created **inside** the repo tree is
absorbed by `pnpm-workspace.yaml`'s globs and pnpm links the workspace copy instead of installing
the tarball — the test then passes without testing anything. And **pnpm 11 cannot run on Node
22.12.0** (`requires at least Node.js v22.13`), so the floor check must consume a built tarball
using **npm and node only**; a floor job written with pnpm fails on the tooling, and the obvious
remedy — raising `engines.node` — abandons the requirement while appearing to fix it.
Output: two shell harnesses, a consumer-side probe, two root scripts, and mutant P10 observed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| packed tarball → foreign consumer project | Everything a consumer sees crosses here; the repo's own `node_modules` must not be reachable |
| repository workspace → scratch project | A scratch directory inside the repo is absorbed by the workspace and defeats the test |
| published artifact → declared runtime floor | `engines.node` is a promise to consumers that only a pinned runtime can check |
| npm registry → scratch install | The scratch install resolves `@standard-schema/spec` from the real registry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-40 | Spoofing | a scratch project silently resolving the workspace copy instead of the tarball | mitigate | `mktemp -d` outside the repo, `npm install` rather than `pnpm add`, and `typescript` installed into the scratch project so no repo-relative compiler is used. The negative control proves the harness can fail. |
