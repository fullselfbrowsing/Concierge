<objective>
Prove the PKG-01 gates fire. Every gate in this phase is a shell exit code, and an exit code never
observed non-zero is indistinguishable from an absent check. Phase 1's ten-mutant battery let three
of ten through on the first draft.

Purpose: success criterion 2 has two halves. "`publint` and `are-the-types-wrong` report no errors"
is the visible half and plan 02-03 already made it green — but green proves nothing about whether
the gates can fail. "A typecheck failure cannot pass the build because the bundler does not
typecheck" is a **structural claim about the pipeline** that no passing command can demonstrate;
the only demonstration is making the gate fire while the build does not. That is mutant P4, and it
cannot be skipped.
Output: mutants P1, P2, P3 and P4 each observed failing their named gate, with the measured
diagnostic recorded.

**This plan modifies no file permanently.** It transiently mutates `packages/concierge/package.json`
and `packages/concierge/src/types.ts`, each applied and restored inside a single
`scripts/mutate-and-prove.sh` invocation with `git diff --exit-code` asserted afterward. It runs in
parallel with plan 02-05 (also wave 3), which transiently mutates the same manifest in its own
worktree; because neither leaves a change, the two cannot conflict.
</objective>

  <action>
    This mutant proves the **pipeline shape**, not any single command. `tsdown` transpiles through
    rolldown, which does not typecheck; `tsc --noEmit` is a structurally separate gate. Nothing that
    passes can demonstrate that. Only the pair can: on one and the same mutant,
    **`pnpm typecheck` must exit non-zero while `pnpm build` exits 0.**

    One `mutate-and-prove.sh` invocation, with a compound gate so both facts are observed on a
    single applied mutation:

    - Target: `packages/concierge/src/types.ts`
    - Pattern: `export const MESSAGE_MAX_CHARS = 180;`
    - Replacement: `export const MESSAGE_MAX_CHARS: 181 = 180;`
    - Gate: `bash -c 'pnpm build; echo BUILD_EXIT=$?; pnpm typecheck'`

    The harness reports PASS when the gate's *final* command — `pnpm typecheck` — exits non-zero.
    The printed `BUILD_EXIT=` line carries the other half. Both are required evidence:

    - `BUILD_EXIT=0` — the bundler happily transpiled a program that does not typecheck. Under
      `isolatedDeclarations: true`, tsdown's dts path is oxc's isolated-declarations transform,
      which emits `declare const MESSAGE_MAX_CHARS: 181;` without checking it against the
      initializer. This is the finding, not an accident.
    - `pnpm typecheck` non-zero with **`TS2322`** — `Type '180' is not assignable to type '181'` —
      reported in `src/types.ts`, and additionally **`TS2344`** in
      `packages/concierge/test-d/results.test-d.ts` on `_messageBound`. Record both.

    Do **not** substitute a mutation that also breaks the build (for example deleting a brace) —
    that would prove the opposite of what this mutant exists to prove. Do not split this into two
    invocations; the pair must be observed on one applied mutation, and one invocation is also what
    guarantees the restore.

    Afterwards, `dist/` holds an artifact built from the mutant (its `.d.ts` says `181`). Run
    `pnpm build` again and confirm `dist/index.d.ts` no longer contains `181`.

    Finally, confirm the ordering that makes the pair matter: CI must run `typecheck` **before**
    `build`. Note in the SUMMARY that plan 02-11's `ci.yml` is required to keep that order, and that
    a `ci.yml` running only `build` would be green on this exact mutant.
  </action>
