scripts/mutate-and-prove.sh <target-file> <literal-pattern> <replacement> -- <gate command...>

  Applies a literal (non-regex) substitution to <target-file>, runs the gate with the mutation
  applied, restores the file, and proves the restoration — all in one invocation.

  Exit codes, each meaningful:
    0  PASS  — the gate exited non-zero (the mutant was caught) and the tree is clean
    1  FAIL  — the gate exited 0 (the mutant escaped)
    2  ABORT — the target file was already dirty before the mutation
    3  ABORT — the substitution was a no-op (the pattern never matched)
    4  ABORT — the target file was not restored

  The gate's own exit code is printed. Callers that need to observe TWO facts about one mutant
  (e.g. P4: `pnpm typecheck` must fire while `pnpm build` must not) pass a compound gate of the
  form `-- bash -c '<cmd-that-must-pass>; echo TAG=$?; <cmd-that-must-fire>'` and assert on both
  the printed TAG line and the script's own PASS.
</interfaces>

  <action>
    Create `scripts/mutate-and-prove.sh`, executable (`chmod +x`), taking
    `<target-file> <literal-pattern> <replacement> -- <gate command...>`.

    Keep these five properties from `02-RESEARCH.md:598-617` **exactly**, because each closes a
    failure mode that was measured:

    1. `set -uo pipefail` — **not** `-e`. The script must survive its own gate failing; that is the
       expected outcome.
    2. **Pre-flight dirty check**: `git diff --quiet -- "$TARGET"` or abort with exit 2. A restore
       must never be able to clobber real uncommitted work.
    3. `trap 'git checkout -- "$TARGET"' EXIT INT TERM` installed *before* the mutation, so
       restoration survives a crashing or killed gate.
    4. **No-op detection**: after substituting, `git diff --quiet -- "$TARGET"` must now report a
       *change*; if it does not, abort with exit 3 and the message
       `ABORT: mutation was a no-op (pattern never matched)`. This is the failure mode that
       produces a green "mutant caught" result while testing nothing — Phase 1's suite had three
       escapees of exactly this family.
    5. `git diff --exit-code -- "$TARGET"` as the post-condition after restoring (abort 4 if it
       fails), not as advice. Then: gate exit non-zero → print `PASS: gate fired (exit N), tree
       clean` and exit 0; gate exit 0 → print `FAIL: gate did NOT fire — mutant escaped` and exit 1.

    **One deliberate departure from the research's verbatim body, and it is mandatory.**
    RESEARCH.md writes the substitution as
    `perl -0pi -e "s/\Q$PATTERN\E/$REPLACEMENT/" "$TARGET"`. The shell interpolates `$PATTERN` and
    `$REPLACEMENT` into the perl source *before* perl parses it, so any `/` in either argument
    terminates the `s///` delimiter and perl dies with a syntax error. That is not hypothetical for
    this phase: mutant P1 replaces `"./dist/index.d.ts"`, and mutant P8 moves a line whose text is
    `} from "./types.js";`. Both contain `/`.

    Pass the pattern and replacement through the **environment** instead, so nothing is interpolated
    into perl's source text: export them as `MUT_PATTERN` and `MUT_REPLACEMENT`, and have the perl
    one-liner read `$ENV{MUT_PATTERN}` / `$ENV{MUT_REPLACEMENT}` into lexicals in a `BEGIN` block,
    then substitute with `\Q…\E` quoting of the pattern lexical. Substitute **once**, not globally.
    Use `-0` (slurp) so multi-line patterns work — P8 needs a nine-line contiguous block. Add a
    comment on that line naming the failure it prevents, in the repo's house style
    (`02-PATTERNS.md` § A, doc-comment-as-diagnostic).

    Header: `#!/usr/bin/env bash`, then a `#` block naming what the script is for and the exit-code
    table. No shell script exists anywhere in this repo — this file establishes the convention that
    a script's header names the requirement or discipline it serves.

    Do not add a `--dry-run` flag, a `-g/--global` flag, a regex mode, or multi-file support. The
    single-target, single-substitution shape is what makes the restore provable.
  </action>
