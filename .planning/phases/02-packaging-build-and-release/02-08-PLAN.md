<objective>
Make the install graph real. Add the two fixture "adapters" that PKG-04's packaging claim needs,
and prove that core as a `peerDependency` resolves to one physical copy from both of them.

Purpose: F1 and F2 in plan 02-07 are runtime guards — they would still pass if someone moved core
from `peerDependencies` to `dependencies` in every adapter, which is exactly the packaging
regression that produces two copies in the first place. F3 is the only fixture in this phase that
catches that, and it is the one that stays meaningful in Phase 9 when the real adapters arrive.
Output: two `private` workspace fixture packages, an extended workspace glob, and a test asserting
both resolve to the same physical directory and the same function object.

**The trap this plan exists to not fall into:** `pnpm-workspace.yaml` globs `packages/*`, which
matches **one level only**. `packages/concierge/test/fixtures/adapter-alpha/` is **not** matched.
Without extending the glob the fixtures are invisible to pnpm, no `node_modules` link is created,
and the realpath assertion silently tests nothing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter manifest → installed graph | Whether core is a peer or a dependency decides whether one or two copies are installed |
| workspace glob → what pnpm sees | A directory not matched by the glob is silently not a workspace member |
| workspace membership → publish set | Every workspace package is a publish candidate unless it is private or excluded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-35 | Tampering / Repudiation | core moved from `peerDependencies` to `dependencies` in an adapter | mitigate | Assertion 1 fails on exactly that edit. No runtime assertion can see it, and it is the packaging change that actually causes two installed copies — which splits the bridge registry, the dedup window and the consent kernel. |
| T-02-36 | Repudiation | a fixture silently outside the workspace, making the guard vacuous | mitigate | The glob is extended with an explanatory comment, and Task 1 asserts both `node_modules` links exist before Task 2 asserts anything about them. |
| T-02-37 | Spoofing | a fixture package accidentally published to npm | mitigate | Both are `private: true`, asserted. Plan 02-10 additionally keeps changesets away from private packages; this plan records the two names it must account for. |
| T-02-38 | Information Disclosure | fixture sources escaping into the published tarball | mitigate | `files` does not list `test`; the packed file list is re-checked after the fixtures exist. |
| T-02-39 | Repudiation | over-claiming what a workspace-symlink test proves | mitigate | The file records that all three resolutions go through pnpm symlinks and names where the published-install evidence actually lives. |
| T-02-SC | Tampering | npm/pnpm installs | mitigate | `pnpm install` here adds only workspace links, no registry packages. `pnpm install --frozen-lockfile` is asserted green afterwards so the committed lockfile matches. |
