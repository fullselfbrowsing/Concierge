<objective>
The phase gate. Run the seventeen-mutant battery, run the shipped-prose audit, run the four
packaging gates, and sign off `05-VALIDATION.md`.

Purpose: this project's standard is that **adequacy is proven by mutation, not by a green suite**. A
test that cannot be made to fail by a named mutant does not count as validation. Every case written in
plans 05-04, 05-05 and 05-06 claims a discriminating mutant; this plan is where those claims are
executed.

**A PASS is not the exit code alone.** `mutate-and-prove.sh` cannot tell WHY the gate exited non-zero,
and a compile failure is indistinguishable from a failing assertion in its output. A mutant that breaks
the build exits 1 at the build step and the script prints "PASS: gate fired (exit 1), tree clean"
having run ZERO tests — proving only that the compiler rejects broken code, which was never in
question. The **caller** must confirm from the gate's OUTPUT that the mutant compiled and that tests
actually ran. A PASS that never ran a test is worse than a FAIL.

Output: recorded mutation results and a signed validation sign-off. No source changes.
</objective>

<interfaces>
`scripts/mutate-and-prove.sh <target-file> <literal-pattern> <replacement> -- <gate command...>`

Exit codes, a published contract other plans already read:
  0 PASS  — the gate exited non-zero (mutant caught) and the tree is clean
  1 FAIL  — the gate exited 0 (mutant escaped)
  2 ABORT — target not tracked, already dirty, or not supplied
  3 ABORT — the substitution was a no-op (pattern never matched)
  4 ABORT — the target file was not restored

The pattern is matched LITERALLY. `perl -0` slurps, so multi-line patterns AND multi-line replacements
both work; use `$'…\n…'` bash quoting to carry a newline in a replacement. There is no `/g` — exactly
one occurrence is replaced, and it is the FIRST one.

Pre-flight: the target must be tracked by git AND clean. Commit everything before starting.

Known limitation 3 — count occurrences **UNFILTERED, comments included**. The script does not skip
comments and `src/bridge.ts` is heavily commented. A pattern occurring once in code and three more
times in prose mutates the DOC COMMENT: the suite stays green and the run is recorded as
"FAIL: mutant escaped", the inverse of the truth.
</interfaces>

**`timeout` (GNU coreutils) is NOT present on this shell** — measured. Do not write `timeout 300 pnpm test`
into any gate. Every gate runs in under two seconds at current suite size.
