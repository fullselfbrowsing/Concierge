<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| validator library → core | `~standard.jsonSchema.input()` is third-party code core calls at module init. It may throw, and it may return anything. |
| developer `jsonSchema` escape hatch → core | A JavaScript consumer can pass an object of any shape through the escape hatch; the type constrains only TypeScript consumers. |
| npm registry → repository | Three new devDependencies enter the lockfile. |
| emitted schema → agent | The emitted JSON Schema is the agent-facing contract for what arguments to produce. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Denial of Service | `emitSchema` root check | mitigate | `emitted["type"] === "object"` or fail. CONTEXT explicitly rejects warn-and-coerce: a malformed root makes OpenAI Realtime reject the *entire* session update, so the agent silently loses every action in that stage (`types.ts:22-28`). The check runs on BOTH the derived and the escape-hatch path. |
| T-03-07 | Denial of Service | third-party `.input()` throwing | mitigate | The call is wrapped in `try`/`catch`; the spec says the converter "may throw" and arktype does. A throw becomes an issue naming the action and the vendor, never an unhandled module-init crash. |
| T-03-08 | Tampering | prototype pollution through emitted keys | mitigate | `Object.keys(...)` only — own enumerable keys. `for...in` is forbidden in this file and asserted absent, because it would walk a `__proto__`-polluted prototype when listing the keys of a hostile emitted schema. |
| T-03-09 | Information Disclosure | failure `detail` strings | mitigate | `detail` carries the action name, the vendor name, the target, the emitted root keys, and `String(cause)` — no argument values, no environment, no file paths. Build-time errors are developer-facing and exempt from the one-generic-sentence rule (`contract.ts:135-138` sets the precedent), but they must never become a channel for anything but their own diagnostics. |
| T-03-10 | Spoofing | reading the spec's `StandardJSONSchemaV1` | mitigate | The converter shape is declared structurally in core, following `AbortSignalLike`. Importing the spec sibling does not compile and pulling `@types/node` or DOM libs to reach around it would defeat the no-DOM guarantee. |
| T-03-SC | Tampering | npm installs (`zod`, `arktype`, `valibot`) | mitigate | RESEARCH's *Package Legitimacy Audit* verified all three on the registry with slopcheck 0.6.1: `[OK]`, no `postinstall`, source repos matching, versions `CLAUDE.md` already names. Exact pins, no carets, no range drift. No `[ASSUMED]` or `[SUS]` package is installed, so no blocking human checkpoint is required. `@valibot/to-json-schema` is declined outright. |
</threat_model>
