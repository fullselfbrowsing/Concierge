# Project Retrospective

*A living document updated after each milestone. Lessons feed forward into future planning.*

## Milestone: v0.1 — First Release

**Shipped:** 2026-08-12
**Phases:** 10 | **Plans:** 93 | **Tasks:** 215 | **Sessions:** not recorded

### What Was Built

- A DOM-free, vendor-neutral TypeScript core whose single action declaration derives types, schema, redaction, stage catalogs, and diagnostics.
- A same-Promise deduplicating dispatcher, live bridge registry, and latest-wins session loop with serial batches, cancellation, and hostile-input containment.
- A delivery-armed, snapshot-bound consent kernel with graded transport authority, canonical readback evidence, one-shot confirmation, and app-authored failure outcomes.
- Thin React and Svelte adapters that share one physical core instance, preserve framework-native lifecycle semantics, and pass server-render and exact-tarball checks.
- A release evidence system covering 62/62 requirements, 455/455 tests, mutation discrimination, clean-clone packaging, inherited evidence, and exact-SHA hosted certification.

### What Worked

- Contract-first sequencing and the rule that nothing published before v0.1 kept breaking type corrections inexpensive through the consent phase.
- Mutation tests required compilation, a positive exact detector, byte-identical restoration, and restored green gates; this repeatedly caught vacuous or misrouted checks.
- Real package and framework consumers exposed defects that source-only tests could not: duplicated core identity, Svelte proxy drift, SSR globals, and package-manager behavior.
- Independent verifier, security, and milestone-audit ownership kept generated evidence from certifying itself.
- Immutable input inventories and exact digests made release evidence reproducible across clean clones and hosted runners.

### What Was Inefficient

- Historical plan prose and validator commands drifted from measured behavior, creating repeated correction and append-only evidence passes.
- Phase 9 evidence had to be resealed after hosted failures exposed shallow Git history and macOS `/tmp` alias handling late in the process.
- Several SUMMARY one-liners described deviations rather than outcomes, so automated milestone accomplishment extraction produced misleading text.
- The milestone archive helper parsed only the final Phase 10 section from the legacy roadmap shape and undercounted the milestone as 1 phase, 7 plans, and 14 tasks; manual reconciliation restored 10/93/215.
- Fine-grained evidence work produced substantial bookkeeping overhead alongside the implementation itself.

### Patterns Established

- Keep mutable runtime state factory-local; authorize through frozen/null-prototype structures and preserve exact Promise identity where identity is contractual.
- Capture hostile or caller-owned capabilities once, detach them, and never expand ambient authority into secure child processes.
- Treat mutation, validation, security, package, workflow, and inherited evidence as one transactional release seal.
- Keep framework adapters lifecycle-thin and make core a peer dependency so bridges, retries, and consent cannot split across instances.
- Represent terminal hosted truth with an attempt-scoped external receipt; never write a post-certification claim into the certified repository.

### Key Lessons

1. Pin hosted infrastructure assumptions—checkout depth, canonical filesystem ownership, artifact cardinality, and job ordering—in local negative-control self-tests before the first remote attempt.
2. A green test is not evidence until the intended defect is observed making that exact test fail; detector identity and nonzero execution counts are part of the contract.
3. Add the framework with the most adversarial reactivity model early. Svelte `$state` made snapshot detachment load-bearing instead of hypothetical.
4. Keep outcome summaries machine-readable and outcome-first; deviation logs belong in their own section.
5. Reconcile milestone counts from on-disk plans and summaries before trusting a parser operating on an evolved roadmap format.

### Cost Observations

- Notable: the highest cost came from evidence regeneration and hosted retry repair, not from the final adapter implementation.
